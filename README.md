## 스터디 방식

### 일정

- `기간`: 2026년 7월 29일 ~ 9월 2일, 정규 6주
- `시간`: 매주 수요일 오후 7시
- `방식`: 온라인을 기본으로 하며 7월 29일과 8월 중 1회는 오프라인 진행
- `공유`: GitHub Issue를 활용한 사전 공유 및 토론

자세한 일정은 [운영 일정](docs/SCHEDULE.md)에서 확인합니다.

### Rules

1. LLM 사용 도구와 방식은 제한하지 않습니다.
2. 매주 가장 기술적인 고민이 많았던 사례 하나를 선정합니다.
3. 월요일 오후 7시까지 주간 사례 Issue를 작성합니다.
4. 스터디 전까지 모든 Issue를 읽고 질문을 준비합니다.
5. 별도 발표 없이 질문과 토론에 집중합니다.
6. 개인 회고는 선택 사항이며 공동 회고는 작성하지 않습니다.

구체적인 참여 방법은 [참여 가이드](CONTRIBUTING.md)를 따릅니다.

## 주간 사례

Issue 제목은 `[Week NN] 이름 - 주제` 형식을 사용합니다.

1. `작업 내용`: 이번 주에 어떤 작업을 했는가?
2. `Deep Dive 해본 것`: 작업 중 어떤 내용을 깊게 살펴봤는가?
3. `알게된 것`: 그 과정에서 새롭게 이해하거나 배운 것은 무엇인가?

[주간 사례 Issue 템플릿](.github/ISSUE_TEMPLATE/weekly-case.md)을 사용해
작성합니다. 위 세 항목 외의 질문, 보충 자료, 토론 내용은 Issue 댓글에
남깁니다.

## 기록 방법

- 주간 사례와 토론은 GitHub Issue에 남깁니다.
- 개인 회고는 `members/<github-id>/week-NN.md` 형식으로 작성합니다.
- 개인 회고 형식은 자유이며 [회고 템플릿](templates/retrospective.md)을
  선택적으로 사용할 수 있습니다.
- 자세한 규칙은 [참가자 기록 안내](members/README.md)를 확인합니다.

## 원칙

> 설명할 수 없는 코드는 내 코드가 아니다.

> LLM의 답도 하나의 의견일 뿐이다.

> 좋은 질문은 좋은 답보다 가치 있다.

> 구현보다 사고 과정을 공유한다.

> 실패한 사례일수록 더 큰 학습이 된다.
