런타임 전환

공개 API 의
실행 모델을 바꿨다

serverless-express 에서 Lambda Web Adapter 로
2026년 9월 6일 운영 반영

인프라를 높은 곳에서 훑고 람다 안까지 내려가서, 거기서 무엇을 왜 바꿨는지까지 갑니다. 마지막은 같이 정할 것 하나로 닫습니다.

오늘 순서

높은 곳에서 시작해 한 층씩 내려갑니다

각 장의 그림은 그 층의 높이에만 맞춥니다. 리전 이야기를 할 때 람다 내부가 나오지 않습니다.

1층. 어디에 있나

서비스는 아일랜드에 있다

거의 전부가 eu-west-1 한 곳입니다. 다른 리전에 있는 것은 CloudFront 와 terraform 상태 파일뿐이고 둘 다 이유가 분명합니다. 리전을 하나로 묶으면 단순해지는 대신 그 리전이 흔들리면 대안이 없습니다.

2층. 누가 만드나

인프라는 두 사람이 나눠 만든다

가르는 기준은 서비스 종류가 아니라 레이어입니다. 람다와 그 앞단 게이트웨이는 코드와 수명을 같이 하므로 SAM 이 갖고, 그 아래 데이터 계층은 terraform 이 갖습니다. 오늘 바꾼 것은 전부 위쪽 상자 안입니다.

2층

terraform 이 만드는 것

여기서 기억할 것은 하나입니다. 프라이빗 서브넷에는 인터넷 경로가 없습니다. 그래서 람다가 시크릿을 읽으려면 VPC 엔드포인트가 반드시 있어야 합니다.

2층

SAM 이 만드는 것

HTTP 표면이 넷인데 바깥에 열린 것은 하나뿐입니다.
공개 표면이 하나라는 사실이
이번 작업의 무게를 정합니다.
그 함수 하나를 바꾸면 로그인부터 파일 업로드까지 전부가 새 실행 모델을 탑니다.
이 문장이 오늘 발표의 핵심 긴장입니다. SSE 와 아무 상관없는 로그인도 같이 검증돼야 했던 이유입니다.

3층. 요청 흐름

요청 하나가 지나는 길

굵은 선이 사용자 요청, 가는 선이 람다가 다시 부르는 것들입니다. 인증과 인가가 전부 이 람다 한 곳에서 끝납니다. 엔진은 인터넷에서 오는 요청을 받지 않습니다.

3층

엔진은 어디에 붙어 있나

엔진은 상시 떠 있는 컨테이너라 스트리밍에 제약이 없습니다. 엔진 코드는 이번 작업에서 한 줄도 바뀌지 않았습니다.
엔진은 흘려보낼 수 있고
게이트웨이도 흘려보낼 수 있는데,
그 사이 람다만 못 흘렸습니다.
이유를 보려면 람다 안으로 들어가야 합니다.
여기서 층을 한 번 더 내려갑니다.

4층. 람다 내부

람다는 어떻게 도는가

왼쪽이 구조, 오른쪽이 수명입니다. 두 가지가 중요합니다. 무엇을 INIT 에 넣느냐가 콜드스타트를 정하고, 핸들러가 값을 반환하는 모양인지가 스트리밍 가능 여부를 정합니다.

4층

기존 구조, serverless-express

Nest 는 원래 포트를 열고 기다리는 웹서버인데 람다는 이벤트를 넘겨주는 모델입니다. 이 둘을 억지로 붙인 것이 어댑터였습니다.
이 어댑터의 정의가
곧 한계였습니다.
Express 응답을 다 모아서 객체 하나로 반환하는 것이 이 어댑터가 하는 일입니다.
낡아서가 아니라 하는 일이 그렇습니다.
이 점을 분명히 해야 합니다. 라이브러리를 업그레이드해서 풀리는 문제가 아닙니다. 실제로 스트리밍 지원 이슈가 2023년부터 열려만 있습니다.

5층. 막힌 지점

왜 SSE 가 안 되는가

SSE 는 답변이 완성되기 전에 조각을 계속 내보내는 방식입니다. 반환하는 구조와 방향이 반대입니다. 그리고 막는 것은 게이트웨이가 아닙니다. 게이트웨이가 SSE 를 흘려 브라우저까지 도달하는 것은 실측으로 확인돼 있습니다.
그래서 라우트를 열기 전에
런타임부터 바꿔야 했습니다.
이 티켓이 SSE 티켓이 아니라 런타임 티켓인 이유입니다.
SSE 라우트를 실제로 여는 일은 다음 티켓입니다. 오늘은 그 앞의 준비까지입니다.
Lambda Web Adapter
AWS 가 만든 레이어입니다. 람다 안에서 평범한 웹서버를 그대로 띄우고 그 앞에서 중계합니다.
이벤트 모델로 감쌀 필요가 없어집니다. Rust 로 만들어져 Node 런타임과 무관하게 돕니다.
배포 방식도 그대로입니다. 레이어 하나를 붙이고 환경변수 몇 개를 주면 됩니다. 컨테이너 이미지로 바꿀 필요가 없습니다.

6층. LWA

LWA 는 이렇게 붙습니다

함수 Handler 가 핸들러 함수가 아니라 기동 스크립트입니다. LWA 가 기동 여부를 확인하는 경로가 필요해서 health 라우트를 새로 만들었고, 호출자 IP 같은 원본 정보는 LWA 가 헤더에 실어 넘깁니다. 이 헤더가 뒤에서 중요해집니다.

7층

스위치가 두 곳에 있습니다

왼쪽 아래 칸은 로그에 아무것도 남지 않습니다. 상태코드는 200 이고 헤더도 멀쩡한데 본문만 없습니다.

하나는 함수에, 하나는 통합에 있습니다. 단위가 다르기 때문에 라우트별로 섞을 수가 없습니다. 그래서 전 라우트가 STREAM 을 탑니다. 배포 후에 바이트가 실제로 오는지 눈으로 확인해야 하는 이유가 왼쪽 아래 칸입니다.

8층. 주변 설정

타임아웃 20초에서 900초로

사용자가 실제로 기다리는 시간은 함수가 아니라 통합이 정합니다. 그 값은 29초 그대로 두었습니다.

스트리밍은 응답이 열려 있는 내내 실행이 살아 있어야 해서 함수 쪽을 올렸습니다. 일반 라우트의 체감은 바뀌지 않습니다.

8층

부팅이 INIT 으로 옮겨갔습니다

전에는 Nest 부팅이 첫 요청 안에서 일어났습니다. 그래서 Provisioned Concurrency 를 켜도 이득이 거의 없었습니다. 환경만 미리 만들어지고 부팅은 첫 요청이 그대로 물었으니까요. 이 이동이 다음 설정의 전제입니다.

8층

동시성 상한을 걷고 PC 를 붙였습니다

전 함수에 동시 실행 1 이 걸려 있었습니다. 스트리밍은 응답이 열려 있는 내내 슬롯을 차지하므로 1 이면 동시 사용자가 1명이 상한입니다. 바닥이 1 이라 평상시 비용은 고정 하나와 같고, 올라가는 것은 트래픽이 실제로 올랐을 때뿐입니다.
숫자를 정확히 말하면 콜드스타트 총량은 평균 2.8초에서 4.1초로 늘었습니다. 최대값만 7.8초에서 4.1초로 줄었습니다. 이걸 개선이라고 부르면 오해입니다.
실제 값은 부팅이 INIT 으로 모여 미리 치를 수 있게 된 것입니다. 평시에는 PC 가 덮어 사용자가 0초를 기다립니다. 웜 요청 속도는 이번 변경과 무관합니다.
이 슬라이드는 일부러 넣었습니다. 처음에 저도 7.8초에서 4.1초로 빨라졌다고 잘못 적었습니다. INIT 끼리 비교한 것이었고, 사용자가 기다리는 것은 INIT 더하기 첫 요청입니다. 늘어난 몫은 LWA 기동과 준비 확인입니다.
로컬에서는 검증할 수 없습니다.
람다 에뮬레이터에 스트리밍 호출 경로가 아예 없습니다. staging 도 만들지 않는 규약입니다.
그래서 같은 템플릿으로 일회성 복제 스택을 올려 확인하고 지웠습니다.
스택 이름만 다르게 해서 복제본을 하나 세웠습니다. 확인이 끝난 뒤 통째로 삭제했습니다. 이 판단이 값을 했습니다.

9층. 결과

확인한 것

  • 함수 기동 정상, 로그에 실패 없음
  • 로그인 전 구간 정상: 발송, 검증, 토큰 발급, 갱신, 회전, 재사용 감지, 로그아웃
  • 중복 헤더로 인한 500 없음
  • 전 라우트 상태코드가 전과 동일
  • 공개 경로 IP 상한 정상 동작
  • API 문서가 공개로 열리지 않음
  • 커스텀 도메인 뒤에서 스트리밍 통과, 본문 실제로 도착
  • 배포 후 에러 0건
로그인을 실제로 완주해서 확인했습니다. 이 티켓이 막고 있던 것이 인증 이슈 여섯 건이라 그게 핵심이었습니다.

9층

복제 스택이 잡은 것 둘

하나 스트리밍 통합 주소의 API 버전. 흔히 쓰는 버전을 적었더니 스택 생성이 400 으로 죽었습니다. 운영에 바로 갔으면 게이트웨이 갱신이 실패해 전 라우트가 영향을 받았습니다.
둘 복제 스택이 워크플로 함수까지 만듭니다. 그 함수는 운영 DB 와 엔진과 푸시로 배선됩니다. 확인용 스택이 운영 워크플로를 1분마다 전진시키고 실사용자에게 푸시를 보낼 뻔했습니다.

둘 다 로컬에서는 재현되지 않습니다.

이 두 개가 복제 스택을 세운 값입니다. 하나는 시끄럽게 죽는 실패라 운영에서도 금방 알았겠지만, 두 번째는 조용히 사고가 됐을 겁니다.

9층

호출자 IP 는 소켓에서 읽으면 안 됩니다

같은 요청에서 동시에 관측한 값입니다. 이 자리는 깨져도 에러가 나지 않습니다.

LWA 뒤에서는 커넥션이 전부 루프백으로 들어옵니다. 소켓 주소를 쓰면 모든 호출자가 같은 값이 되어 상한이 사라지는 게 아니라 전원이 막힙니다. 회귀 테스트를 따로 붙여 뒀습니다.
